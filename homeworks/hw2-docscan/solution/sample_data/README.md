# ДЗ 2 — кадры курса и ожидаемый вывод

Пять кадров 1280 × 960 «лист A4 на столе» с **точно известными углами** (`corners.json`), страница
«в лоб» (`page-gt.png`, 744 × 1052) и ролик (`clip.mp4`, 640 × 480, 60 кадров). Кадры нарисованы,
поэтому углы известны до пикселя — на своих снимках такой роскоши не будет. Прогоните свои команды
здесь **до того**, как снимать свой набор: расхождение больше допуска — ошибка в функции, а не
«другая машина».

| Кадр | Что на нём | Зачем он в наборе |
|------|-----------|-------------------|
| `desk.jpg` | лист на тёмном деревянном столе, ровный свет, рядом ручка | оба пути должны сработать |
| `corner.jpg` | кружка стоит на углу листа, свет падает слева (1 → 0.5), через лист — тень | контур не замкнут: путь контуров ничего не находит; тень — для этапа 5 |
| `tiles.jpg` | лист повёрнут на плитке со швами | длинные посторонние прямые — испытание для пути Хафа |
| `plain.jpg` | белый лист на светлом столе | слабый перепад: правило медианы для порогов Canny здесь слепнет |
| `nosheet.jpg` | листа нет: книга, кружка, ручка | правильный ответ — «не найдено»; книга — тоже четырёхугольник |
| `clip.mp4` | лист едет по столу 45 кадров, в последних 15 его нет | видеорежим без камеры |

Ниже `S` — этот каталог, `L3 = lectures/L03-color-histograms/demo` репозитория курса. Числа получены
эталонной реализацией на OpenCV 4.14.0.94. Допуски: IoU ± 0.01, σ шума ± 0.1, совпадение чернил ± 1 %;
миллисекунды и FPS — порядок величины, они зависят от машины. Путь Хафа случаен: при другом способе
брать случайные пары точек ваши углы разойдутся в десятых долях пикселя, а число успехов из 20 —
на 1–2.

## 1. Шум

```
python docscan.py noise S/desk.jpg       → noise_sigma 0.99      (рабочий кадр 640 × 480)
python docscan.py noise S/corner.jpg     → 2.22
python docscan.py noise S/tiles.jpg      → 1.73
python docscan.py noise S/plain.jpg      → 0.99
python docscan.py noise S/nosheet.jpg    → 1.73

python docscan.py noise S/desk.jpg --add-sigma 5     → оценка 5.44 · σ фильтра 1.53 · остаток: измерено 0.92, по формуле 0.92
python docscan.py noise S/desk.jpg --add-sigma 10    → оценка 10.38 · σ фильтра 2.93 · остаток 0.96 / 0.96
python docscan.py noise S/desk.jpg --add-sigma 25    → оценка 24.71 · σ фильтра 3.00 (предел) · остаток 2.34 / 2.35
```

Сцены нарисованы с шумом σ 3–6 в полном кадре; в рабочем кадре (уменьшение вдвое усредняет четыре
пикселя, плюс JPEG) остаётся 1–2 кода. Оценка через **медиану** модуля на `desk.jpg` держится
в пределах 9 % от добавленной σ; через среднее — хуже: на странице текста при σ = 6 медиана даёт
6.9, среднее — 8.4.


## 3. Лист: два пути

```
python docscan.py detect S/desk.jpg --method contour --ann S/corners.json -o out/desk_contour.jpg
python docscan.py detect S/desk.jpg --method hough   --ann S/corners.json -o out/desk_hough.jpg
```

| Кадр | `contour` IoU | `hough` IoU (зерно 0) | `hough`: успехов из 20 зёрен | `auto` |
|------|---------------|-----------------------|------------------------------|--------|
| `desk.jpg` | 0.994 | 0.998 | 20 | 0.994 — контуры |
| `corner.jpg` | **не найден** | 0.995 | 20 | 0.995 — Хаф |
| `tiles.jpg` | 0.980 | 0.996 | 18 | 0.980 — контуры |
| `plain.jpg` | **не найден** | **не найден** | 0 | не найден |
| `nosheet.jpg` | «не найдено» ✔ | «не найдено» ✔ | 20 | «не найдено» ✔ |

Углы на `corner.jpg` путём Хафа: (330.5, 120.3), (904.3, 169.7), (985.1, 848.3), (216.2, 768.5) при
истинных (330, 120), (905, 170), (985, 850), (215, 770): все четыре — в пределах 2 px, включая
угол под кружкой, которого в кадре не видно: он восстановлен пересечением прямых.

Что видно уже на пяти кадрах:

- **Контуры — быстро и хрупко:** 7–10 мс, но закрытый угол (`corner.jpg`) — и контура нет.
- **Хаф + RANSAC — медленнее и точнее:** 35–60 мс; IoU 0.995–0.998 против 0.98–0.99 у контуров —
  прямая по сотне точек точнее обводки; но на плитке два зерна из двадцати промахиваются.
- **`plain.jpg` не находит никто** — и дело не в путях, а в порогах (этап 2).
- **`nosheet.jpg`** с ключом `--no-paper-check` путь контуров принимает за лист книгу:
  углы (160, 404), (612, 360), (656, 776), (180, 848). Готовая проверка `looks_like_paper`
  (внутри светлее, чем вокруг) её отсекает.

## 4. Сводка по набору и пороги Canny

```
python docscan.py eval S --ann S/corners.json --seeds 20 --csv out/eval.csv --overlays out/eval
python docscan.py eval S --ann S/corners.json --seeds 20 --canny 50,150
python docscan.py eval S --ann S/corners.json --seeds 20 --close 0
```

Листов найдено (IoU ≥ 0.9) из четырёх · средний IoU · кадр без листа отклонён:

| Настройка | `contour` | `hough` | `auto` | `hough`, успехов из 20: desk / corner / tiles / plain |
|-----------|-----------|---------|--------|-------------------------------------------------------|
| по умолчанию: пороги от медианы, закрытие 9 | 2 · 0.493 · да | 3 · 0.747 · да | 3 · 0.742 · да | 20 / 20 / 18 / 0 |
| `--canny 50,150` | 3 · 0.741 · да | 3 · 0.747 · да | **4 · 0.989** · да | 20 / 20 / **4** / 20 |
| `--canny 20,60` | 3 · 0.739 · да | 2 · 0.715 · да | 4 · 0.988 · да | 12 / 18 / 2 / 20 |
| `--close 0` | 2 · 0.493 · да | **0 · 0.000** · да | 2 · 0.493 · да | 0 / 0 / 8 / 0 |

Читается так: правило медианы теряет `plain.jpg`; фиксированные 50 / 150 его возвращают, но на
плитке путь Хафа начинает цепляться за швы (4 зерна из 20) — выручает то, что `auto` сначала пробует
контуры; ещё ниже пороги — Хаф сыплется уже и на дереве. Без закрытия текста путь Хафа не работает
совсем. Это пять нарисованных кадров — на ваших пятнадцати картина будет своя, её и нужно измерить.

## 5. Скан

```
python docscan.py scan S/corner.jpg -o out/corner_scan.jpg --bw out/corner_bw.png --gt S/page-gt.png
  углы найдены путём Хафа → выход 773 × 1093 (W / H 0.707)
```

Совпадение чернил с `page-gt.png`, % (ключ `--binarize`):

| Кадр | выход | `otsu` | `adaptive` | `flat` |
|------|-------|--------|-----------|--------|
| `desk.jpg` | 737 × 1042 | 87.7 | 91.3 | 92.4 |
| `corner.jpg` (свет 1 → 0.5 и тень) | 773 × 1093 | **73.0** | 93.2 | **94.0** |
| `tiles.jpg` | 539 × 762 | 86.2 | 89.4 | 91.1 |
| `plain.jpg` с `--canny 50,150` | 626 × 885 | — | — | 92.3 |
| `desk.jpg` с `--corners` из разметки | 741 × 1048 | — | — | 94.4 |

Сто процентов здесь недостижимы: штрих шрифта в кадре — один-два пикселя, и половину расхождения
даёт ресемплинг, а не порог (с идеальными углами — 94.4 %). Важна разница между методами: на кадре
с тенью Otsu принимает тень за чернила (73 %), деление на фон возвращает 94 %.

Отдельно этап 5 — на странице из L3, где эталон совпадает пиксель в пиксель:

```
python docscan.py binarize L3/text-lamp.png --gt L3/text-gt.png -o out/lamp.png
  otsu 56.8 % · adaptive (31, 15) 98.8 % · flat 99.9 %             (первые два числа — слайд 38 L3)
```

## 6. Видео

```
python docscan.py video --source S/clip.mp4 --method auto --no-window --seconds 0
  frames 60 · found_pct 75.0 (лист — в 45 кадрах из 60) · FPS — порядка сотни: файл читается быстрее камеры
```

То же для `--method contour` и `--method hough`: 75.0 %; путь Хафа — около 35 мс на кадр.
`--seconds 0` — до конца файла. С камерой (`--source 0`) FPS ограничен самой камерой, обычно 30.
