## 2. Три вопроса

**2.1. Какое цветовое пространство выбрано для хромакея и почему? Что было бы в RGB?**

HSV: цвет предмета живёт в H, освещение — в V, поэтому границы задаются по оттенку и насыщенности,
а V остаётся открытым (40…255). Проверено переносом границ, снятых с мяча при дневном свете, на
кадр под лампой: по HSV recall 94.8 % при precision 99.8 %, по тем же процентилям прямо в B, G, R —
recall 6.1 % при precision 0.7 % и маска 16.14 % кадра вместо эталонных 1.72 %. Причина: в RGB смена
освещения двигает все три координаты сразу, и коробка, выделявшая мяч днём, под лампой указывает в
пустое место цветового куба, тогда как в HSV уехала в основном V, а границы по H сдвинулись лишь с
140…166 на 149…171. 

**2.2. Что происходит с гистограммой при γ < 1 и при γ > 1? Куда деваются обрезанные пиксели?**

γ = 0.5 сдвигает гистограмму вправо: среднее 115.3 → 161.1, медиана 118 → 173, тени растягиваются
(p1 с 2 до 23), доля чистого чёрного падает 0.10 → 0.04 %. γ = 2 — зеркально: среднее 115.3 → 69.9,
медиана 118 → 55, тени сжимаются до обрезки, доля чёрного прыгает 0.10 → 5.11 %. Обрезанные пиксели
не исчезают, а слипаются: таблица 255·(x/255)² переводит все входные уровни 0…11 в один выходной 0,
поэтому 5.11 % кадра становится ровно нулём и различить внутри них исходные значения уже нельзя.
Это необратимо — обратная гамма растянет 0 в 0, а не в 0…11; у γ = 0.5 по той же причине из 256
выходных уровней занято только 192.

**2.3. Почему CLAHE лучше `equalizeHist` на своём фото — по числам из 1.3?**

По σ в тенях: 12.0 у исходника → 14.4 у `equalizeHist` → 20.0 у CLAHE, то есть +39 % к глобальной
эквализации. Причина в сюжете: светлая часть кадра — экран ноутбука, тёмная — стена, и одна общая
кривая, обслуживая светлую половину, в тенях почти плоская, а CLAHE растягивает каждую плитку
8 × 8 отдельно. Второй довод — света: `equalizeHist` уводит их 213.2 → 229.9, CLAHE 213.2 → 203.5,
то есть глобальная кривая пересвечивает и без того яркий экран. На равномерно недоэкспонированном
кадре вывод переворачивается: на `ball-lamp.jpg` курса (σ в тенях 8.3, светов нет) `equalizeHist`
поднимает света 116.3 → 229.5, а CLAHE только до 157.4 — там нужен именно глобальный метод.

## 3. Где сломалось

**Команда:** `wb --method grey-world` на `data/bright.jpg`.

**Что получилось:** по таблице 1.2 метод отработал идеально — средние каналов 141.3 / 142.0 / 142.7.
По факту белый стол, единственная заведомо серая поверхность в кадре, уехал в фиолетовый
(`experiments.py wb-reference`, опора — светлые ненасыщенные пиксели, 0.34 % кадра):

| | стол B / G / R | разброс на столе | разброс средних по кадру | обрезано B = 255 |
|---|---|---|---|---|
| исходник | 209 / 238 / 243 | 34.2 | — | — |
| grey-world | 255 / 211 / 201 | 53.7 | 1.4 | 100.0 % |
| white-patch | 247 / 254 / 249 | 7.6 | 62.1 | 42.5 % |

**Причина:** grey-world предполагает, что средний цвет сцены серый, а здесь 36.2 % площади — жёлтая
обложка книги. Среднее по кадру уехало в жёлтый, и метод компенсировал не лампу, а саму книгу:
усиление по синему 1.500 против 0.827 по красному. Разброс на столе стал хуже, чем был до коррекции
(34.2 → 53.7), и весь синий канал стола упёрся в 255 — информация потеряна необратимо.

**Что помогло бы:** считать среднее не по всему кадру, а по пикселям с низкой насыщенностью; либо
брать медиану вместо среднего; либо, как здесь, white-patch — он держится за 99-й процентиль, то
есть за сам стол, и большая цветная область ему не мешает (разброс на столе 7.6).
